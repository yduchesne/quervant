# PR 15E-A — exact-workload CPU and allocation profiling

Standard-library-only profiling harness for the **frozen PR 15D v1 exact-term
Quervant workload**. It wraps the unmodified `pr15d-quervant-adapter` in `perf`
(CPU samples) or `heaptrack` (allocation traffic), validates every reply against
the independent PR 15D oracle, and produces fail-closed, checksummed evidence.

This directory does **not** contain an optimization, an instrumentation hook, a
second query implementation or a measurement result. It produces the evidence a
separately reviewed PR 15E-B can cite.

See the dossier in [`docs/pr-artifacts/pr-15e-a/`](../../docs/pr-artifacts/pr-15e-a/)
for the current status, the decision log and the test traceability matrix.

## Why a new driver

PR 15D-B already builds the frozen corpora, the real `FsDirectory` index and the
three adapters. PR 15E-A reuses those helpers (`harness/run.py`,
`corpus/generate.py`, `corpus/oracle.py`) and adds only what a profiler needs: a
child process that is *wrapped* by the profiler while still speaking the frozen
`pr15d-adapter-v1` JSONL protocol. The driver never evaluates a query itself and
never edits `benchmarks/pr15d/`.

## Fixed matrix (20 captures, no other combination is authorized)

| N | K | Class | Tools | Profiled seconds |
|---:|---:|---|---|---:|
| 10000 | 100 | absent, rare, medium, common | perf, heaptrack | 20 |
| 100000 | 100 | absent, rare, medium | perf, heaptrack | 30 |
| 100000 | 100 | common | perf, heaptrack | 60 |
| 100000 | 10 | absent, rare, medium | perf | 30 |
| 100000 | 10 | common | perf | 60 |

Every capture uses one adapter process, one `QuerySession`/`ReaderSnapshot`, five
untimed warmups and then a bounded loop of identical requests. Every reply is
checked against `oracle.expected()`; a single mismatch is a hard stop.

## Workflow

```sh
# 1. Prepare (clean tracked tree required): corpus, release adapter with
#    debuginfo, both FsDirectory indexes, oracle expectations and one real
#    adapter smoke query per lane.
python3 benchmarks/pr15e/profile.py prepare --out target/pr15e/<run-id>

# 2. Capture one authorized lane inside an operator-attested idle window.
python3 benchmarks/pr15e/profile.py capture --run target/pr15e/<run-id> \
  --n 100000 --class common --k 100 --tool perf --seconds 60 --idle-confirmed

# 3. Verify every artifact, then (only from complete evidence) publish a
#    sanitized manifest.
python3 benchmarks/pr15e/verify.py --run target/pr15e/<run-id>
python3 benchmarks/pr15e/verify.py --run target/pr15e/<run-id> \
  --analysis target/pr15e/<run-id>/analysis.json --publish-manifest
```

Exit codes: `0` success / `EVIDENCE_COMPLETE`, `2` invalid invocation, `3`
blocked, `4` failed, `5` hard stop, `6` unsafe path.

## Attestation

A capture requires `<run>/attestation.json` that the operator wrote verbatim from
their own statement (never generated by the agent):

```json
{
  "schema": "pr15e-attestation-v1",
  "host": "<hostname>",
  "start_utc": "YYYY-MM-DDTHH:MM:SSZ",
  "end_utc": "YYYY-MM-DDTHH:MM:SSZ",
  "operator_statement": "Host <hostname> is idle from <UTC-start> to <UTC-end> on <date>; I authorize PR 15E-A CPU and heap allocation profiling for the frozen PR 15D workload in that window."
}
```

`--idle-confirmed` alone is never evidence. The driver also requires a clean
tracked tree, `HEAD` equal to the prepared source SHA, an unchanged corpus,
index, adapter binary and frozen PR 15D sources, `seconds + 120` of remaining
window, and a `clear` contention probe before and after the capture.

## Evidence layout (`target/pr15e/<run-id>/`, gitignored)

```text
prepare.json                    corpus/binary/index/oracle/source lock
attestation.json                operator window (local only)
corpus/                         frozen PR15D TSVs + manifest
build/release/…                 adapter built with CARGO_PROFILE_RELEASE_DEBUG=1
indexes/n<N>/                    immutable committed FsDirectory index
captures/n<N>/<class>/k<K>/<tool>/
  capture.json                  manifest (CAPTURED_RAW) with per-file hashes
  perf.data, perf-self.txt, perf-calltree.txt
  heaptrack*.gz, heaptrack-report.txt
  contention-before.json, contention-after.json, profiler-stderr.txt
verification.json               fail-closed re-derivation of every capture
analysis.json                   (optional) attributed attribution entries
```

Raw profiler artifacts are private evidence. `verify.py --publish-manifest` only
writes `benchmarks/reports/pr15e-a/profile-manifest.json` from complete evidence,
refuses test fixtures, and refuses content that leaks absolute paths, hostnames
or usernames.

## Tool capability preflight (recorded facts, not assumptions)

- `perf`: `/usr/bin/perf` on WSL2 is a distro wrapper that refuses a kernel
  mismatch. A pre-installed versioned binary (`/usr/lib/linux-tools/*/perf`) is
  selected and recorded, with the wrapper failure and kernel mismatch preserved
  as evidence (decision matrix X12). No package is installed and no shim is
  created.
- `heaptrack` 1.5.0 **prints two informational lines to stdout before launching
  the debuggee** (`heaptrack output will be written to …`, `starting application,
  this might take some time...`). The driver therefore refuses to treat a
  heaptrack capture as qualified: a non-JSON line on the adapter stream is an
  X22 hard stop, not something to skip. See
  [`decision-log.md`](../../docs/pr-artifacts/pr-15e-a/decision-log.md).

## Tests

```sh
# Deterministic driver/verifier tests (fake profiler processes only at the
# process boundary; all fixture evidence is labelled TEST_FIXTURE).
python3 -m unittest discover -s benchmarks/pr15e -p 'test_*.py' -v

# Real Quervant adapter + real FsDirectory 10K/100K index + real oracle.
PR15E_RUN_REAL_INTEGRATION=1 python3 -m unittest \
  test_profile.RealAdapterIntegrationTest -v
```

Fixture evidence can never be published: `verify.py --publish-manifest` rejects
any manifest marked `test_fixture`.
