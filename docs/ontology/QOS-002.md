# QOS-002 — Relationship archetypes and inference

**Version 1.0-design · Approved conceptually · Post-v0.1**

## Three layers

1. **Characteristics** are logical traits of relationships.
2. **Archetypes** are reusable built-in/user-defined roles, rules and constraints.
3. **Relationship types** are domain-named definitions explicitly bound to archetype roles.

The inference engine is generic and must not hardcode domain relationship names.

## Built-in hierarchy

`quervant.hierarchy` defines roles `parent`, `child`, `ancestor`, `descendant`. Child is inverse of parent; ancestor is **strict transitive closure** of parent; descendant is inverse of ancestor. Parent graph is acyclic and permits multiple parents. Ancestor and descendant are derived-only and cannot be asserted directly. Additional archetypes may express symmetric association, transitivity, inverse pairs and equivalence; equivalence does **not** merge document identity.

## Composition and rules

User archetypes can import immutable version-pinned archetypes and extend roles/rules/constraints monotonically; weakening/removing imported constraints is prohibited. Strengthened constraints require compatibility validation.

Inference rules are finite, positive, range-restricted Datalog-like binary rules: no negation, arithmetic, entity creation, arbitrary code or side effects. Recursive SCCs use bounded least-fixed-point evaluation: `E = lfp(X ↦ F ∪ T_P(X))`. `siblingOf` cannot be inferred from symmetry alone (shared-parent siblings require inequality, outside the initial rule fragment). `antonymOf` symmetry does not imply logical complement.

The canonical compiled ontology records definitions, versions, normalized rules, dependencies/SCCs, constraints, hierarchy bindings and a semantic fingerprint. Invalid programs and inconsistent data are rejected. Specialized inference is allowed only if provably equivalent to the general reference semantics.
