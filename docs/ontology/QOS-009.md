# QOS-009 — Ontology Discovery and Agent-Oriented Query Planning

**Version:** 0.1-proposal | **Status:** proposed, **not approved** | **Delivery:** post-v0.1, unassigned

## Purpose and boundary

Define an agent-neutral, machine-readable interface by which clients discover a pinned index ontology, ground semantic identifiers, validate typed query plans, execute bounded combined search/ontology queries, and interpret completeness. This is an architectural proposal, not an implementation authorization, public API freeze, or amendment to QOS-001–QOS-004.

Quervant owns deterministic catalog resolution, query validation, execution, budgets, and results. Agents own natural-language interpretation, decomposition, sequencing, external-tool usage, and answer synthesis. No embedded LLM, LangGraph dependency, mandatory MCP transport, arbitrary executable rules, or automatic ontology mutation is required. The core API must be usable without agents.

## Dependencies and compatibility

- QOS-001: index-local instances, class inheritance, named hierarchies, asserted vs effective facts, complete validation.
- QOS-002: approved finite positive range-restricted rule language, fixed-snapshot least-fixed-point semantics.
- QOS-003/003A/003B/003C: atomic publication, forward/reverse asserted adjacency, pinned snapshots, independent inference above asserted storage, cache fingerprints, invalidation and resource limits.
- QOS-004: canonical operator URNs, exact ambiguity errors, scope resolution, snapshot/operator/ontology plan binding.
- QOS-005: *proposed* proof/explanation interface; QOS-009 must not claim evidence-backed proof details until QOS-005 is approved.
- [GRAPH-ONTOLOGY-INTEGRATION](GRAPH-ONTOLOGY-INTEGRATION.md): proposed graph query composition and relationship-view contract.
- QOS-008 remains distinct hypothetical-state research, not authorized inference over committed snapshots.

## Candidate logical interfaces (no wire-format or Rust API commitment)

### 1. DiscoverCapabilities

Read-only capability negotiation bound to a specific index and requested snapshot. Return supported catalog and query schema revisions, enabled query families, operator URNs, relationship views, graph traversal modes, proof support (if available), streaming/pagination availability, and defined limit categories. Advertise *supported*, *unsupported*, or *requires separate extension*; do not imply graph shortest-path, a proof service, or distributed inference already exists. Capability records have schema version and stable semantic fingerprint; clients must revalidate on fingerprint change.

### 2. DescribeOntology / SearchOntology

Expose bounded, paginated, typed entries for classes, direct and inherited membership semantics, relationship types, characteristics, domain/range, archetypes, rules (safe metadata only), hierarchy families, namespaces, and operators. Include canonical URNs, display names/aliases, signatures, argument positions/types, descriptions if supplied, ontology version and fingerprints. Search by canonical URN/name/alias/text with explicit ambiguity; no automatic selection by best match. A page is tied to one pinned snapshot and catalog revision. Visibility and authorization filtering must not leak inaccessible definitions.

### 3. ValidateQuery / ExplainPlan

Accept a typed, versioned query expression/IR containing resolved canonical operator URNs or resolvable names plus an explicit scope. Resolve using QOS-004; reject unknown, ambiguous or colliding identifiers. Check arity, type compatibility, family availability, relationship view, supported composition and operator capabilities *before execution*. Return either a canonicalized snapshot-bound plan plus non-authoritative diagnostics and budget estimates, or structured errors; no execution or mutation. Estimates are not proof of available resources. Plan fingerprints bind snapshot, ontology, registry and query schema. Never silently broaden a user's request by substituting another relation.

### 4. ExecuteQuery

Consume a valid pinned plan (or validate and execute atomically under the same snapshot). Permit mixed lexical/typed/temporal/geospatial predicates with class-membership/ontology predicate evaluation, subject to existing support and the graph composition extension. Support parameters/bindings and bounded result projections, including canonical instance incarnation identifiers, source document identity, asserted/effective classification when meaningful, snapshot identifiers and explicit evaluation status. Return full semantic completion or an explicit partial/indeterminate/error status; budget exhaustion is never false, not-found, or success. A conclusive positive witness may be returned even if optional proof enumeration is incomplete; distinguish truth completeness from explanation completeness.

### 5. Continuation and multi-step planning

Quervant exposes deterministic query results, schema, diagnostics, parameter contracts and snapshot-bound continuation tokens. The agent decides subsequent queries and must pin the same snapshot for reproducibility or explicitly acknowledge a new snapshot. No server-side conversational state, natural-language-to-query correctness guarantee, or opaque automatic multi-step agent orchestration is specified. Continuation tokens bind identity/authorization context, snapshot, plan fingerprint and ordering; expired snapshots/tokens return explicit errors, never transparently restart.

## Proposed typed query composition examples (illustrative, not grammar)

- Filter documents with a time predicate AND `IsInstanceOf(i, CloudIdentity)` under a pinned ontology.
- Enumerate *asserted* `member_of` outgoing neighbors of an identity, then test an *effective* `IsDescendantOf` relationship; no implicit asserted/effective substitution.
- Filter graph path endpoints with ordinary indexed predicates while traversing only an explicitly selected relationship view; bounds and snapshot are shared.
- Request an explanation only if a QOS-005-compatible proof capability is advertised, otherwise return a typed unsupported result.

## Query security and resource model

Catalog, validate and execute require index authorization; definition visibility and query authorization are separate checks. Reject mixed-tenant/index identifiers and references to deleted incarnations; never infer authorization from ontology membership. Prevent user-provided text/labels from acting as instructions. No secret source documents in diagnostics, logs or result metadata without authorization.

Specify and enforce unified budgets for operator resolution, catalog enumeration, candidate documents, adjacency records/segments, graph vertices/edges/frontier, rule firings/SCCs, inferred facts, memory/spill, remote ObjectStore bytes, output size, open cursors and deadline/cancellation. A plan may use a separate optional explanation budget, but may not mint fresh independent traversal/inference budgets for nested operators. Fail closed on unsupported or exhausted operations. No whole-graph opening/materialization.

## Result/error contract (candidate categories)

Typed outcomes differentiate `COMPLETE_TRUE`, `COMPLETE_FALSE` (only after conclusive evaluation), `INDETERMINATE`, `UNSUPPORTED`, `INVALID_QUERY`, `STALE_SNAPSHOT`, `UNAUTHORIZED` and `RESOURCE_EXHAUSTED`. These are illustrative logical categories, not frozen tokens. Pagination of an otherwise valid result set must distinguish incomplete page consumption from incomplete inference. Respect QOS-005's distinct proof enumeration completeness if enabled.

## Acceptance criteria before approval / implementation

1. Define a versioned catalog schema with canonical identifiers, fingerprint behavior, inheritance/archetype metadata, pagination and permission filtering.
2. Define typed query IR and validation errors with operator scope ambiguity, typed arity errors and snapshot/plan mismatch cases.
3. Define composition semantics and unified budgets with the graph/ontology contract; include sorted/top-K, cursor, streaming and negative-predicate completeness.
4. Demonstrate reference workflows: cross-class cloud identity discovery; ATI observed domain→IP→ASN inference with external evidence links; multi-query refinement, including stale-snapshot handling.
5. Provide adversarial fixtures for missing facts, disjointness, cycle/retraction, ambiguous alias, unsupported capabilities, budget exhaustion, cancellation, compaction and recovery.
6. Independent reference-evaluator cross-check of ontology truth values; catalogs and query plans stable across compaction; no silent partial-success.
7. Decide exact public interface, capability names, authorization/visibility, protocol adapters, rollout staging and distributed compatibility in future approval PRs.

## Explicit non-goals

No full OWL/RDF/SPARQL compliance claim; no automatic hallucination-resistant natural-language translation guarantee; no scoring of logical truth as probability; no AWS built-in permission evaluator; no QOS-008 state-transition solver; no implied implementation of graph centrality/community/shortest-path; no ontology editing by agents; no modification of v0.1 or v0.2 acceptance.

**Decision gate:** proposal only. Review and explicitly approve normative QOS-009 contracts before implementation planning.
