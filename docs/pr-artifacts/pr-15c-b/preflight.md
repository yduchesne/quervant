## 6. Adverse cases and known environment defect

### 6.1 Pre-existing documentation defect (not repaired)

`docs/TESTING.md` lines 56–59 contain four literal `<<<<<<< HEAD` markers with no
matching `=======`/`>>>>>>>` hunks. Reproduced by `git blame` against commits from
2026-10-11/12, therefore pre-existing. Per the plan ("Do not silently repair
pre-existing `docs/TESTING.md` merge-conflict markers") this PR does not edit it.

### 6.2 Installed profilers collide with the frozen PR 15B validator (open defect)

`benchmarks/scripts/capture-pr07-env.sh` records `perf_path`,
`cargo-flamegraph_path` and `heaptrack_path` from `command -v`.
`validate-pr15b.py::build_trial` then sets

```python
profiler_status = "UNAVAILABLE" if all(p == "UNAVAILABLE" for p in paths) else "AVAILABLE"
```

and always writes `profiler_evidence = None`, while
`validate_pr15b.py::validate_trial` requires non-empty evidence whenever the status
is `AVAILABLE`. The PR 15B qualification host had **no** profilers installed
(`target/pr15b/20261028T161528Z-e8ca1b0…/trial-1/env.txt` records all three as
`UNAVAILABLE`), so the rule never fired. On the current host the profilers were
installed during the PR 15B profiling follow-up
(`docs/pr-artifacts/pr-15b/profile-attempts.md`), so **every** trial produced by
the frozen runner on this host is structurally unqualified. Reproduced directly:

```text
derived profiler_status = AVAILABLE
REJECTED: AVAILABLE profiler status requires captured evidence
```

This blocks S3 qualified measurement and is **not** covered by any preauthorised
row of the decision matrix. It is recorded as **STOP-15CB-01** (rule X99) in
`decisions.md`. It does not block S1, S2, S4, S5 or S6 evidence.
`perf` is additionally version-mismatched with the WSL kernel (6.8.12 generic
binary on a 6.18 kernel), which is recorded as a profiling caveat, not a pass.
