# QGS-005 — Unified graph/search query planning

**Version:** 1.0-design | **Status:** conceptually approved | **Delivery:** unassigned.

## Decisions

- **QP-001.** Versioned canonical typed logical IR (semantics) separate from physical IR (execution), independent of future SQL/Cypher syntax; include search, typed/JSON, time, geo, graph, ontology and eventual vector sources. Reuse QOS-004 canonical operator URNs and fingerprints.
- **QP-002.** Typed graph pattern variables, labeled vertex/edge patterns, directed and bounded variable-length paths, explicit optional/existence semantics when implemented. Parallel edge bindings retain edge IDs.
- **QP-003.** Binding relations have bag semantics by default; projection, filter, join, semi/anti-join, union, distinct, grouping, sorting, aggregation and expansion; negative tests require complete evaluation.
- **QP-004.** Search/graph joins with incarnation-aware Vertex↔Document mapping; no assumed document for graph-only vertex. Indexed nested loop, batched adjacency join, hash and merge join, semi-/anti-join; bounded memory/spill.
- **QP-005.** Typed predicate positions: seed, edge eligibility, entry, continuation, terminal/result, whole path and post-aggregation. Only semantics-preserving pushdown; cannot move terminal-only filters inside traversal, discard parallel edges or illegally push limit.
- **QP-006.** Cost vector includes CPU, memory, local/remote I/O, network, cardinality; graph degree, edge-type, label, property selectivity, tombstone/cache statistics and confidence in estimates. Approximate statistics never justify unsound result pruning.
- **QP-007.** Bounded optimizer search over access paths and join orders, dynamic programming for small conjunctive patterns, heuristics for large patterns; specialized variable-length operator preserves WALK/TRAIL/SIMPLE_PATH.
- **QP-008.** BM25, path cost, centrality, aggregation and final score are distinct; rankings may combine only via explicit typed functions. Top-K pushdown needs equivalence proof.
- **QP-009.** Single pinned local index generation for mixed plans. Cross-index/distributed snapshots must be separately qualified; no implied global transaction.
- **QP-010.** One global resource meter covering planning, joins, scans, graph traversal, inference, remote reads, memory, spill, output and cancellation; no work-limit reset at operator boundaries.
- **QP-011.** Composable finite demand-controlled batch operators (SearchScan, VertexScan, AdjacencyExpand, Filter, Join, Aggregate, Sort, PathExpand, GraphAlgorithm). Identify blocking stages, preserve terminal success/error and backpressure.
- **QP-012.** EXPLAIN identifies logical/physical plan, canonical URNs, estimates, join order, predicate placement, projection and snapshot fingerprints, budgets and pipeline breakers; ANALYZE measured costs without sensitive values by default.
- **QP-013.** Explicit asserted/effective ontology relation sources with QOS inference, reference equivalence, cache fingerprints and no fictional inferred multigraph edge identities.
- **QP-014.** Distributed-ready logical plans and versioned exchange boundaries; runtime exchanges/shuffle are not v0.2 promises.
- **QP-015.** Authorization-aware validation and mandatory policy checks non-reorderable unless proven safe; independent small-query logical evaluator and optimized-plan differential tests.

## Required correctness examples

Duplicate parallel edges yield distinct bag bindings; DISTINCT collapses only requested keys. An anti-join cannot report absence after budget exhaustion. Global top-K after join is not generally equivalent to top-K before join. Snapshot and authorization requirements apply to all plan operators. Any unsupported plan/operator version rejects explicitly.

## Phases

P0 logical IR and identity joins; P1 indexed joins/batched expansion; P2 general joins and safe pushdown; P3 cost optimizer; P4 diagnostics/aggregation/streaming qualification. General SQL/Cypher and distributed join execution not part of v0.2.
